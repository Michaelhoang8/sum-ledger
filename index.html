Inspect the exact reference

The accumulator adds integer multiples of 2⁻¹⁰⁷⁴ using BigInt. It rounds only once, to nearest with ties to even. Exact zero has no preserved sign. 


        

          The reference is exact for the parsed binary values. It is not the
          exact sum of the original decimal fractions: 100 copies of 0.01
          illustrate this distinction.
        

      

      

        How the methods differ
        

          Naive adds from left to right. Kahan carries a correction into the
          next addition. Neumaier also compensates when the new term is larger
          than the running sum. Pairwise recursively divides the ordered
          sequence at its midpoint, sums both halves, then combines them.
        

        

          The error is measured against the exact binary sum, not just its
          rounded display. A correctly rounded result can still have a nonzero
          exact error. The condition estimate uses rounded totals and can
          overflow; it is a sensitivity indicator, not an error bound. These
          methods use binary64 throughout; the exact reference uses a separate
          BigInt representation.
